# Market Agents — 系统说明文档

> A 股多智能体市场行为推断与状态择时框架 — 从多源行情/资金流数据出发，经 NMF 行为分解、HMM 市场状态识别与仓位优化，完成批量回测与组合分析。

## 1. 核心理念

传统量化策略从价格出发（技术指标、统计套利），**Market Agents** 的出发点是：

**先把市场参与者的行为模式分解出来，再基于这些行为模式判断市场状态，最后将状态映射为仓位。** 

不直接问"涨还是跌"，而是问"当前市场由谁在主导、处在什么阶段"，再决定如何应对。

核心流程：
1. **行为分解** — 用 NMF 将日频价格/资金特征矩阵分解为若干隐式"交易主体"的活跃度序列
2. **状态识别** — 将活跃度序列与量价/资金流特征合并，通过 HMM（隐马尔可夫模型）或规则分类器识别市场状态（恐慌→狂热五档）
3. **仓位优化** — Walk-forward 搜索各状态对应的最优仓位映射
4. **回测验证** — 含涨跌停/印花税/滑点等 A 股实盘摩擦

此外，系统还包含**五智能体订单簿仿真**模块，用于在分钟级别模拟市场微观结构（散户/机构/量化/宏观/热钱），验证行为分解的合理性。

## 3. 数据流详解

### 3.1 数据采集 Pipeline

```
股票池（全市场 4992 只 A 股）
  │
  ├── 日线数据 (daily_bars.parquet)
  │     ohlc / 复权因子 / 成交量 / 换手率
  │
  ├── 分钟数据 (minute_bars.parquet)
  │     1分钟 ohlc / 成交额
  │
  ├── 资金流 (fund_flow.parquet)
  │     主力净流入 / 散户净流入 / 超大单/大单/中单/小单
  │
  ├── 北向资金 (northbound.parquet)
  │     北向净流入
  │
  ├── 融资融券 (margin.parquet)
  │     融资余额变化 / 融券余额
  │
  ├── 新闻 (news.parquet)
  │     相关个股新闻 / 行业新闻
  │
  └── 行业映射
        东方财富行业 → 申万一级 → 中信行业（可选）
```

增量拉取通过 `scripts/拉取全市场.py` + `后端/采集/批量拉取.py` 实现，只拉取缺失日期，断点续跑。

### 3.2 NMF 行为分解

核心假设：市场价格和交易量的变化可被少数隐式的"交易主体"行为解释。

```
输入：日频特征矩阵（300+ 维度 × N 天）
  - 成交量相关：开/高/低/收、成交额、换手率
  - 分钟聚合特征：日内波动率、RSI、VWAP偏差
  - 资金流特征：主力/散户净流入比
  └─ 归一化 → 非负矩阵

NMF 分解 → W (N×K) + H (K×M)
   ├─ W：每日各 Agent 的"活跃度"时间序列
   └─ H：每个 Agent 的"行为指纹"（哪些特征贡献最大）

Agent 解释：
  基于 H 中权重最大的特征，为每个 Agent 赋予语义角色
  例如：Agent_0 → "动量散户"、Agent_1 → "逆势机构"、Agent_2 → "量化高频"……
```

### 3.3 市场状态识别

将 NMF 活跃度 + 分钟量价特征 + 资金流特征合并，构建状态特征，然后用两种方法识别市场状态：

**路线 A — HMM（隐马尔可夫模型）**

```
状态特征 →
  高斯混合模型(GMM) 聚类 → n_states 个簇
  按 forward_return 或收益率/波动率排序映射为语义状态
  → 恐慌 / 震荡偏弱 / 横盘 / 震荡偏强 / 狂热

HMM 特性：
  - 输出状态转移矩阵
  - 预测下一交易日各状态概率
  - 自动捕捉状态的时序依赖性
```

**路线 B — 规则分类器（备选）**

```
基于加权评分规则：
  bull_score = 收益率 × 100 + 主力净流入比 × 0.3 + Agent活跃度 × 0.2
  stress_score = 波动率 × 0.4 + 成交量异常 × 0.4 + 负收益惩罚
  
  恐慌: stress > 0.65 && bull < -0.2
  震荡偏弱: 其余低 bull 场景 ...
  横盘: 中间区域
  震荡偏强: bull > 0
  狂热: bull > 0.5 && stress < 0.4
```

默认仓位映射：

| 市场状态 | 建议仓位 |
|----------|----------|
| 恐慌 | 0% |
| 震荡偏弱 | 30% |
| 横盘 | 50% |
| 震荡偏强 | 80% |
| 狂热 | 100% |

### 3.4 仓位映射优化

Walk-forward 网格搜索覆盖默认仓位映射：

```
对每个状态遍历 0~100% 仓位（按 step 步长）
  → 优化目标：最大化 Sharpe / 最小化回撤 / 自定义 objective
  → Walk-forward 分割：前 70% 训练 + 后 30% 样本外验证
  → 输出最优仓位映射表
```

### 3.5 回测引擎

回测引擎模拟 A 股实盘交易的完整摩擦：

| 摩擦项 | 默认值 | 说明 |
|--------|--------|------|
| 佣金 | 0.03% | 双边 |
| 印花税 | 0.05% | 仅卖出 |
| 滑点 | 0.05% | 双边 |
| 涨跌停 | ±9.8% | 无法成交时保持原仓位 |
| 停牌 | — | 自动跳过 |
| 最小仓位限制 | 可配置 | 避免极低仓位频繁交易 |

### 3.6 五智能体订单簿仿真

分钟级微观市场仿真，用于验证 NMF 分解结果的合理性：

| 智能体 | 策略 | 参数可校准 |
|--------|------|-----------|
| **零售散户 (Retail)** | 动量追涨、恐慌杀跌 | momentum_sensitivity, chase_threshold |
| **机构 (Institutional)** | VWAP 逆势建仓 | reversion_sensitivity, vwap_entry_threshold |
| **量化 (Quant)** | RSI 超买超卖 | signal_sensitivity, rsi_oversold/overbought |
| **宏观 (Macro)** | 开盘尾盘集中交易 | active_minutes_window |
| **热钱 (Hot Money)** | 追日内脉冲 + 高波动 | momentum_threshold, vol_spike_threshold |

校准方式：
- **矩匹配校准**：对比模拟产生的分钟统计量（波动率自相关/收益率分布/量价相关性）与真实数据，调整智能体参数
- 校准结果持久化到 `calibrated_params.json`

### 3.7 残差分析

将 NMF 基线（agent_activity × 系数 ≈ 主力净流入）与实际资金流的差作为残差。残差异常日可能对应：

- 未被 NMF 捕获的突发事件
- 新的交易主体出现
- 数据异常

可选通过本地 LLM（Ollama）对残差日进行文本解释。

### 3.8 批处理与增量分析

```
全市场批处理（4992 只股票）：
  1. 准备清单：获取全市场股票代码（东方财富/baostock）
  2. 增量下载：只拉取缺失日期的数据
  3. 分批分析：对每只股票运行管线（特征→NMF→状态→回测）
  4. 结果入库：策略收益/Sharpe/最新状态 → PostgreSQL
  5. 行业汇总：按行业聚合表现

断点续跑：记录每个股票的处理状态，中断后从上次位置继续
```

## 8. 核心设计决策

### 8.1 为什么用 NMF 做行为分解？

- **非负性约束**：NMF 要求所有成分非负，分解出的"活跃度"天然可解释（0=不活跃，越大越活跃）
- **加性结构**：市场总特征 ≈ 各 Agent 特征的加权和，符合"市场由多类参与者共同驱动"的直觉
- **无需先验知识**：NMF 自动从数据中提取因子，不需要预设哪些交易主体存在

对比 PCA：PCA 允许负权重（某成分负向贡献），物理意义模糊。NMF 的"部分构成整体"更符合行为分解场景。

### 8.2 为什么做状态择时而不是方向预测？

状态择时的核心假设是 **"市场状态是持续且可识别的"**。恐慌期不会一天结束，狂热期也不会突然消失。

- **方向预测**：问"明天涨还是跌" → 高噪声、低胜率
- **状态择时**：问"当前在恐慌/震荡/狂热哪个阶段" → 状态持久性降低噪声，适合仓位管理

### 8.3 HMM vs 规则分类器

| 维度 | HMM | 规则分类器 |
|------|-----|-----------|
| 需要训练 | 是（GMM 聚类） | 否 |
| 状态时序依赖性 | 自动建模（转移矩阵） | 无记忆 |
| 可解释性 | 中等（状态含义需映射） | 高（显式规则） |
| 对新样本 | 需重新聚类 | 即插即用 |
| 推荐场景 | 研究阶段、样本内分析 | 快速原型、稳定版生产 |

### 8.4 五智能体仿真 vs 实际数据

仿真并非要精确预测价格，而是：

1. **验证 NMF 结果的可逆性**：如果能从真实数据分解出 Agent，再用这些 Agent重建仿真数据，仿真产生的统计量应与真实数据匹配
2. **参数敏感性分析**：了解不同 Agent 的参数变化如何影响市场统计量
3. **反事实推演**：如果某类 Agent 行为参数改变，市场会如何演化？

校准（矩匹配）提供定量的仿真与真实数据拟合度评估。

### 8.5 全市场批处理设计

A 股全市场 4992 只股票的处理采用分层设计：

```
股票池层：东方财富/baostock 获取清单 → stocks_index.csv（增量更新）
   │
数据层：akshare 按代码拉取 → 本地 Parquet 缓存（断点续跑）
   │
分析层：逐只运行管线 → 结果入 PostgreSQL / 本地缓存
   │
聚合层：按行业/风格/市值汇总 → 组合推荐
```

每个环节支持独立的增量运行 `--status` 查看进度，`--batch-size` 控制并发。

## 11. 扩展指南

- **新增数据源**：在 `采集/数据源.py` 注册 `FetchFn`，实现拉取函数
- **新增状态方法**：在配置 `state.method` 中切换 `hmm` / `rule`，或在 `推断/` 中新增分类器
- **新增仿真 Agent**：在 `仿真/智能体.py` 中定义新 Agent 类，在 `仿真引擎.py` 中注册到主循环
- **新增批量标的**：编辑 YAML 配置的 `batch.symbols` 或通过 `--symbols 000001,600000` 参数
- **集成新前端组件**：按 `源码/页面/` 下现有结构新增 Vue 页面，在 `接口/路由.py` 注册对应 API
