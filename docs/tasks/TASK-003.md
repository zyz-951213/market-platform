## R12 A/B 实测(2026-10-06,**纯缓存重放,零 API 调用**)

问题:`market-platform 自检` 一直在报 —— `backtest.strategy.stop_loss=0.08`、`take_profit.enabled=true`
在 unified 主路径上**完全不执行**(它们在 `continue` 之后)。本轮把它实现成开关
`portfolio.unified_sharpe.apply_risk_controls` 并做三组对照(同一份缓存,只改开关与参数)。

| 组 | 配置 | 总收益 | 夏普 | 最大回撤 | 触发次数 |
|----|------|--------|------|----------|----------|
| A(生产口径) | 风控关闭 | **+121.31%** | **0.8824** | **-11.67%** | — |
| B(v1) | 开,基准=进攻袖贡献,无冷却 | +73.92% | 0.7726 | -11.67%(无改善) | 止损 388 / 止盈 40 / 移动止盈 2104 |
| C(v2) | 开,基准=账户净值,冷却 10 根 | +108.04% | 0.8279 | **-13.09%(更差)** | 止损 1 / 止盈 148 / 移动止盈 0 |

**结论:接入 legacy 式止损/止盈到六袖统一账本,两头都不讨好 —— 收益下降,回撤没有改善(甚至变差)。**
因此配置**保持 `enabled: false`**,并在配置注释里写明原因与证据位置。

为什么语义不成立(诊断):

1. v1 把触发基准放在"进攻袖累计贡献"上,而最大回撤是按**账户净值**衡量的:
   阈值对前者过紧(2104/2700 ≈ 78% 的 bar 都在触发),对后者又完全动不了。
2. v2 换成账户口径并加冷却后,触发显著收敛(止盈 148 次),但**在上涨途中频繁削减进攻袖**
   正是收益来源,于是收益掉 13 个百分点;而账户回撤由防守/现金流袖主导,削减进攻袖改不动它。
3. 统一账本本身已有风险管理:`group_caps` 硬投影 + 滚动夏普加权 + `risk_off` 叠加(进攻 ×0.42)。
   再加一层 legacy 式择时止损属于**重复且互相抵消**的控制。

**顺带产出**:`strategy_fingerprint` 现在把 `portfolio` 配置纳入指纹(此前改 unified 配置在历史记录里
没有任何痕迹),所以三组实验在 `指数预测.回测记录` 里各有独立指纹、可区分复核。
`回测记录.指标` 新增披露字段:`统一风控启用`/`统一风控触发`/`dropped_bars`/
`failed_train_blocks`/`failed_predict_bars`/`unified_fallback_reason`。
